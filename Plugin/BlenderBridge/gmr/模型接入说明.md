# GMR 模型接入说明

**你不需要改任何 Python 源码。** 接入模型只需两件事：填一份 JSON 配置表，提供符合契约的函数。

---

## 为什么是配置表

初版在 `train.py` 与 `sidecar.py` 里留了 5 处 `TODO`，要求你直接改我们的骨架代码。这有两个实际问题：

- 每次 `git pull` 都可能冲突
- 换模型时得先把上一个模型的代码删掉，而不是改一行配置

所以改成了配置驱动。原先的 5 处 TODO 现在是配置表里的 5 组 `module` + 函数名：

| 原 TODO 位置 | 现在的配置项 |
|---|---|
| `train.py` → `build_model()` | `model.module` + `model.factory` |
| `train.py` → `train_one_epoch()` | `training.module` + `training.trainStep` |
| `train.py` → `save_checkpoint()` | `checkpoint.module` + `checkpoint.saver` |
| `sidecar.py` → `load_model_impl()` | `model.module` + `model.loader` |
| `sidecar.py` → `infer_impl()` | `sampler.module` + `sampler.sample` |

骨架代码负责 import、调用、错误处理、状态机；你负责提供模型逻辑。

## 三步接入

### 1. 复制配置表

```bash
cd gmr/
cp model_config.example.json model_config.json
```

`model_config.json` 已在 `.gitignore` 语义上属于本地配置——它是你的私有选择，不该进版本库。

### 2. 填写配置

至少要改这几处：

```jsonc
{
  "enabled": true,                    // ← 必须改为 true，否则走降级路径

  "runtime": {
    "sysPath": ["/你的/模型仓库/根目录"]   // ← 让 import 找得到模型代码
  },

  "skeleton": {
    "joints": 22,
    "fps": 30,
    "window": 64,
    "upAxis": "Y",                    // ← 填错会让角色躺平，见下方警告
    "featureDim": 263
  },

  "model":      { "module": "你的模块", "factory": "构造函数名", "loader": "载入函数名" },
  "dataset":    { "module": "你的模块", "loader": "数据加载函数名" },
  "training":   { "module": "你的模块", "trainStep": "单步训练函数名" },
  "checkpoint": { "module": "你的模块", "saver": "保存函数名" },
  "sampler":    { "module": "你的模块", "sample": "采样函数名" }
}
```

### 3. 校验

直接运行加载器就能排错，不必启动训练：

```bash
# 只看配置是否合法
python3 python/model_config.py

# 同时尝试 import 并解析全部入口（需要模型代码就位）
python3 python/model_config.py --resolve
```

`--resolve` 的输出示例：

```
OK   model.factory -> build_model
OK   model.loader -> load_checkpoint
-    dataset.loader (未配置)
FAIL training.trainStep
     无法 import 模块 'condmdi.train_loop'（来自 training.module）: No module named 'condmdi'
       提示：未配置 runtime.sysPath。若模型代码在独立仓库中，需把仓库根目录加进去。
```

接模型时最耗时的往往是判断「到底是路径不对还是函数名不对」，所以错误消息刻意写得具体，还会列出该模块里可见的名字。

## 六个函数契约

所有函数都会收到完整的配置字典 `config`，便于读取自己那一节的参数（如 `config["sampler"]["steps"]`）。

### `model.factory` — 构造模型

```python
def build_model(config: dict, device: str):
    """从零构造模型。训练时调用（除非传了 --resume-from）。"""
    return MyModel(**config["model"]["initArgs"]).to(device)
```

### `model.loader` — 载入权重

```python
def load_checkpoint(config: dict, checkpoint_path: str, device: str):
    """载入已有权重。sidecar 装载模型、以及训练续跑时调用。"""
    # 安全要点见下方「安全须知」
    return MyModel.load(checkpoint_path, map_location=device)
```

### `dataset.loader` — 数据加载

```python
def build_dataloader(path: str, config: dict):
    """返回任何可迭代对象。每次迭代产出的 batch 会原样传给 trainStep。"""
    return torch.utils.data.DataLoader(
        MyDataset(path),
        batch_size=config["training"]["batchSize"],
        **config["dataset"]["loaderArgs"],
    )
```

未配置此项时 `trainStep` 会收到 `batch=None`，需自行取数据。

### `training.trainStep` — 单步训练

```python
def train_step(model, batch, optimizer, config: dict) -> dict:
    """
    返回本步指标 dict，数值项会被自动求平均后写进 epoch 日志。

    注意：反向传播、梯度裁剪、optimizer.step() 全部由你负责。
    框架不代管——不同模型的反向时机差异很大（如 diffusion 的多步损失），
    越权代管只会碍事。
    """
    loss = model.compute_loss(batch)
    optimizer.zero_grad()
    loss.backward()
    if config["training"].get("gradClip"):
        torch.nn.utils.clip_grad_norm_(model.parameters(), config["training"]["gradClip"])
    optimizer.step()
    return {"loss": loss.item()}
```

### `checkpoint.saver` — 保存权重

```python
def save_safetensors(model, path: str, meta: dict) -> None:
    """
    meta 含骨架契约与当前 epoch，建议一并写入权重文件。
    训练成功后 Node 侧会读 done 文件，把这个 path 自动登记进模型注册表。
    """
    safetensors.torch.save_model(model, path, metadata={"gmr": json.dumps(meta)})
```

### `sampler.sample` — 生成推理

```python
def sample_with_constraints(model, constraints: list, window: list, seed: int, config: dict):
    """
    constraints 与 Blender 侧挂在 Empty 上的 gmr_* 自定义属性一一对应：
      {"type": "sparse",   "joint": "foot_L", "frame": 30, "loc": [x,y,z], "rot": [...]}
      {"type": "fullbody", "frame": 0,        "pose": [[...], ...]}

    window 是 [起始帧, 结束帧]。
    返回逐帧数据 list[list[float]]，长度应为 window[1] - window[0] + 1。
    """
    return my_ddim_sample(model, constraints, window, seed,
                          steps=config["sampler"]["steps"])
```

## 降级路径：不配置也能跑

`model_config.json` 不存在、或 `enabled: false` 时：

| 组件 | 行为 |
|---|---|
| `train.py` | dry-run：模拟训练、产出占位 checkpoint |
| `sidecar.py` | `/infer` 走三次贝塞尔插值兜底 |

**降级路径不需要 PyTorch。** 它的用途是验证整条链路——Node 侧状态机、日志读取、SIGTERM 取消、done 文件解析、自动登记模型、Blender 与 sidecar 的通信——而这些与模型无关。

这正好对应论文第一阶段「用传统插值顶替 ML-Betweener」的做法，也是 README 里排的 **S0**。

**建议先在降级路径下把 S0 做完再接模型。** 理由是故障隔离：此时若出问题，问题一定在 `bpy` 侧，不可能来自模型。

---

## 部分配置也可以

配置项不是全有或全无。已解析的入口会被使用，缺失的走降级：

| 已配置 | 结果 |
|---|---|
| 仅 `sampler` + `model.loader` | 能推理，不能训练 |
| 仅 `model.factory` + `training.trainStep` + `checkpoint.saver` | 能训练，推理仍走兜底 |
| 配置了但 `import` 失败 | 记录 `config_error`，降级兜底，**sidecar 不会崩** |

sidecar 是常驻服务，配置错误让它退出会直接断开 Blender 侧连接。所以它选择降级并把原因暴露在 `/health` 的 `config_error` 字段里。

## 热重载

改完配置不必重启 sidecar：

```bash
curl -X POST http://127.0.0.1:6091/reload_config
```

模型实例不受影响。若更换了 `model.loader`，需再调 `sidecar_load_model` 重新装载。

## 超参优先级

**命令行 > 配置表 > 内置默认。**

命令行优先是刻意的——这样 Agent 通过 `train` 命令传参时能覆盖配置表，便于同一份配置跑不同规模的实验：

```
train dataset=... epochs=5      # 快速试跑，覆盖配置表里的 epochs: 50
```

## 安全须知

**PyTorch checkpoint 走 pickle 反序列化，加载不受信任的文件等同于任意代码执行。**

你的 `model.loader` 实现里若用 `torch.load`，务必：

```python
torch.load(path, map_location=device, weights_only=True)
#                                     ^^^^^^^^^^^^^^^^^^ 必须
```

更好的做法是用 **safetensors**，它在格式层面就不支持执行代码。这也是 `registry.js` 的 `SAFE_FORMATS` 只列 `safetensors` / `onnx` / `npz` 的原因，以及 `import_model` 拒绝 URL 的原因。

## ⚠️ upAxis：最常见的接入事故

**多数动作模型是 Y-up，Blender 是 Z-up。**

填错的表现是角色躺在地上。这个错误不会报异常，只会让结果看起来「模型烂得莫名其妙」，所以特别难查。

配置校验器会在 `upAxis` 缺失时直接拒绝启动，但**它无法判断你填的值是否与训练数据一致**——这一项只有你知道。

---

## ⚠️ 延迟：rig 与批处理的分水岭

交互式拖拽需要 **~100-150ms**。

原生 DDPM 1000 步采样绝无可能达到。必须用 **DDIM / LCM 少步采样**，或蒸馏模型。配置表里 `sampler.steps` 默认给的是 `10` 而非上游默认值，就是这个考虑。

`sidecar.js` 在单次推理超过 300ms 时会主动返回性能警告。

单次请求可临时覆盖步数，便于在质量与延迟之间快速权衡：

```
infer constraints=... steps=5
```

## 关于模型选型

论文用的两个模型权重都没有公开：

| 论文用的 | 状态 | 替代 |
|---|---|---|
| **IBMM**（Implicit Bézier Motion Model, MIG 2025） | 未开源 | **CondMDI** — 论文原文自己写了 "our framework is compatible with other generative motion engines" 并引用 Cohan et al. 2024，即 CondMDI |
| **ML-Poser**（基于 ProtoRes, ICLR 2022） | 权重未公开 | **Blender 原生 IK** — 第一版直接顶替，省掉一整个模型 |

`model_config.example.json` 里的模块名（`condmdi.model` 等）是**按 CondMDI 的形态写的示意**，不是真实存在的 API。实际接入时请按上游仓库的真实模块结构填写。

## 排错清单

| 现象 | 检查 |
|---|---|
| 一直走贝塞尔兜底 | `enabled` 是否为 `true`；`/health` 的 `sampler_ready` 与 `config_error` |
| `No module named 'xxx'` | `runtime.sysPath` 是否指向仓库根目录 |
| 「模块中没有 xxx」 | 函数名拼写；错误消息会列出该模块可见的名字 |
| 角色躺平 | `skeleton.upAxis` |
| 拖拽卡顿 | `sampler.steps` 太大；换 DDIM/LCM |
| 训练秒结束且产物是 json | 走了 dry-run，说明 `training.trainStep` 未解析成功 |
| `sampler.sample 返回了 None` | 你的实现漏了 `return` |
